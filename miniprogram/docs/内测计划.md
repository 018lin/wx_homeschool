# 凌田家校 · 家校共育系统 内测计划（上线前）

| 项目 | 内容 |
| --- | --- |
| 被测对象 | 微信小程序 `miniprogram/`（36 个页面 + 3 个自定义组件）+ 后端 `server.js`（Node 原生 HTTP）+ Neon PostgreSQL |
| 线上后端 | `https://wx-homeschool-1.onrender.com`（`miniprogram/utils/api.js:12`） |
| 角色 | `parent` / `student` / `teacher` / `admin`（账号全部由管理员创建，**无自助注册**） |
| 文档版本 | v1.0（2026-10-16） |
| 适用范围 | 上线前内部测试（体验版 + 正式版灰度），不含 Web 端 HTML 页面 |

## 0. 测试策略与总览

### 0.1 测试分层

| 层级 | 内容 | 手段 |
| --- | --- | --- |
| L1 接口层 | 45+ 个 API 契约、鉴权、参数校验 | 已有 `test/core-api.test.js`（node --test）+ 手动 curl/Postman |
| L2 单页功能 | 每个页面的数据渲染、交互、空态 | 真机手工 |
| L3 端到端闭环 | 跨角色、跨页面的完整业务链路 | 多机多角色并行 |
| L4 非功能 | 性能、弱网、兼容性、安全 | 真机 + 开发者工具 |

### 0.2 缺陷分级

| 等级 | 定义 | 上线要求 |
| --- | --- | --- |
| **P0 阻断** | 主流程不可完成 / 数据丢失 / 越权可见他人数据 / 小程序崩溃 / 白屏 | 必须清零 |
| **P1 严重** | 核心功能异常但有替代路径、金额/统计口径错误、账号被踢异常 | 必须清零或明确降级方案 |
| **P2 一般** | 文案错误、样式错位、非核心交互异常、提示不明确 | ≤5 个可带病上线，需登记 |
| **P3 体验** | 动画、空态文案、可优化项 | 可延期 |

## 1. 维度一：用户核心流程（端到端闭环，优先级最高）

> 每条链路需要**至少 2 台真机 / 2 个账号**并行验证，重点看「另一端能否立刻看到」。

### E2E-01 管理员建号 → 家长首登建档 → 领任务 → 提交 → 教师批阅 → 家长看反馈 ★主链路

| # | 步骤 | 关键校验点 |
| --- | --- | --- |
| 1 | 管理员 `admin/accounts` 建教师/学生/家长/班级账号 | 建号成功返回 `id`/`childId`；重名 409 `ACCOUNT_EXISTS`；学生填的 `parentAccount` 不存在 → 400 `PARENT_NOT_FOUND` |
| 2 | 家长首次登录 | 被 `/api/home` 的 `needQuestionnaire` 劫持到问卷页 |
| 3 | 家长填问卷 | 提交后自动绑定孩子并跳转首页；**重复提交问卷会新建孩子档案**（需确认是否为预期） |
| 4 | 教师 `teacher/publish` 发布本周全班任务 | 家长端首页立刻出现任务卡，`taskStatus=ongoing` |
| 5 | 家长 `parent/task` 存草稿 → 正式提交 | 草稿可反复覆盖；正式提交后**锁定不可改** |
| 6 | 教师 `teacher/submissions` 查看详情 → AI 生成点评 → 发布 | 点评落库，家长端 `unreadCount` +1 |
| 7 | 家长 `parent/feedback` / `parent/timeline` 查看 | 反馈可见；**注意 `/api/timeline` 会把未读反馈清零**，需在 timeline 之前/之后分别核对红点 |

**回归重点**：步骤 5 重复正式提交应 409 `SUBMISSION_EXISTS` 且不产生重复数据。

### E2E-02 家长提成长关注 → AI 生成草案 → 教师审核 → 生成定制任务 → 家长端+学生端收到 ★闭环

| # | 校验点 |
| --- | --- |
| 1 | 家长 `parent/concern` 描述 <4 字被前端/后端拦截（400 `请至少写 4 个字描述…`） |
| 2 | 提交后返回 `aiStatus`：`ai` / `fallback`，列表状态为 `pending` |
| 3 | 教师 `teacher/requests` 打开详情，**表单必须用 AI 草案预填，不出现家长原话**（语义红线） |
| 4 | 教师「同意实施」→ 生成 `child_id` 定制任务，家长端首页出现该任务 + 通知 |
| 5 | 学生端首页出现「老师定制」标识任务 + `student_custom_task` 通知 |
| 6 | 教师「拒绝」**必须填原因**，否则 400；家长端能看到 `teacher_comment` |
| 7 | 同一条反馈二次审核 → 409 `REQUEST_ALREADY_REVIEWED` |

### E2E-03 教师录校园观察 → 校对推送对象 → 确认推送 → 家长收到 ★含 AI 匹配

| # | 校验点 |
| --- | --- |
| 1 | 语音或文字录入 → 只生成**草稿**进入「待校对」清单（不直接推送） |
| 2 | `recipientSource` 四种：认出学生 / 推给全部可见家长 / 认出学生但无家长 / 无对象；后两种必须可手动补选家长 |
| 3 | 校对弹层：可勾选增删家长、改 `summary` / `parentMessage` |
| 4 | 确认推送（单条 / 一键全部）→ 二次确认 → 家长端「校园观察」通知 |
| 5 | 已发送列表展开：家长送达/已读状态 |
| 6 | **18:00 自动补发**：未确认的草稿由 cron 每 10 分钟拉起 `scripts/auto-send-daily-updates.js` 补发；验证补发不重复（幂等） |
| 7 | 删除草稿；`autoSendTime` 默认值展示正确 |

### E2E-04 学生提小心事 → 管理员回复 → 学生看到回复并消提示 ★

| # | 校验点 |
| --- | --- |
| 1 | 学生 `student/worry` 提交（空内容 400；>500 字 400） |
| 2 | 管理员 `admin/worries` 顶部「有 N 条新提交」（`newCount` 不受 limit 影响） |
| 3 | 管理员回复（>500 字 400；**重复回复会覆盖并重置 `reply_read_at`**） |
| 4 | 学生端首页出现「老师回复了你的 N 条小心事」提示 |
| 5 | **学生只在 `student/worry` 页看到回复后才标记已读** → 首页提示消失；只逛首页不点进去，提示必须保留 |
| 6 | 管理员打开列表即标记 `read_at`，新提交提示清零 |

### E2E-05 家长 ⇄ 教师 站内私信 ★

| # | 校验点 |
| --- | --- |
| 1 | `pages/messages` 联系人列表可见范围（后端 `getMessagePeerIds`）符合预期：家长能找到本班教师 |
| 2 | 进入 chat，6s 轮询刷新，对方消息 ≤6s 内到达 |
| 3 | 每次拉取后 `markMessagesRead(peerId)`，未读数清零 |
| 4 | 退出页面停止轮询（不出现后台持续请求 / 内存泄漏） |
| 5 | 非管理员访问无权限 `peerId` → 403 |

## 3. 维度三：高频使用场景（真实使用节奏）

| # | 场景 | 测试要点 |
| --- | --- | --- |
| H-01 | **家长周一早上看本周任务** | 周一边界：`mondayOf()` 由服务器算，周日仍属**上一周**；跨周切换时旧任务消失、新任务出现的时机；用户本地时区与服务器（+08:00）不一致时的显示 |
| H-02 | **家长晚上陪孩子做任务并提交** | 高峰时段并发提交；附件上传弱网；提交后页面状态立刻变更 |
| H-03 | **教师下班前批量批阅 20 份提交** | 连续 AI 生成点评（每份 5-15s）不卡死；列表状态实时更新；中途退出不丢已发布点评 |
| H-04 | **教师每天录 3-5 条校园观察** | 语音转写准确率；连续录音内存；18:00 未确认自动补发 |
| H-05 | **管理员开学批量建 100+ 账号** | 批量建号耗时；重名冲突提示；列表渲染性能（无分页，一次性返回） |
| H-06 | **家长反复在 4 个 tab 间切换** | 页面栈深度（无 tabBar，全靠 `redirectTo`）；返回行为一致；`onShow` 重复请求不闪屏 |
| H-07 | **学生用家长手机 / 家长用学生账号** | 角色守卫拦截（见 §6） |
| H-08 | **弱网/地铁/电梯场景** | 见 §7.3；GET 自动重试一次的表现；loading 遮罩不卡死 |
| H-09 | **小程序被系统杀后台后再进** | `app.onLaunch` 从 storage 恢复 token；token 失效 → 401 → 清 session → 跳登录 |
| H-10 | **教师用 AI 助手连续追问** | 上下文 history 正确；新会话清空；网络中断回退非流式 |

## 4. 维度四：边界与异常情况

### 4.1 输入边界

| # | 用例 | 预期 |
| --- | --- | --- |
| B-01 | 任务标题/内容只输入空格 | 前端 trim 后拦截，或后端 400，不入库空数据 |
| B-02 | 提交内容/心事/回复输入 emoji、超长文本、特殊字符 `<>&"` | 正常入库与回显，**不出现 XSS 或渲染错乱** |
| B-03 | 附件：0 个 / 6 个 / 7 个 | ≤6 通过，第 7 个提示「最多 6 个」 |
| B-04 | 附件：15MB / 15.1MB；类型 gif / pdf / docx | 超限与非法类型均 400 `INVALID_ATTACHMENT`，提示明确 |
| B-05 | 录音 1 秒 / 60 秒 / 超时自动停止 | <500ms 不转写；60s 自动停；转写 2MB 上限 |
| B-06 | 头像：超大原图 / 非图片 / 1×1 像素 | 压缩到 320×320；超限提示「头像图片过大」；恢复默认头像（传空串） |
| B-07 | 改密：5 位 / 65 位 / 纯数字 / 纯字母 / 与原密码相同 / 两次不一致 | 逐条命中对应文案 |
| B-08 | 问卷年龄 2 / 3 / 18 / 19 / 小数 / 负数 | 仅 3-18 通过 |
| B-09 | `childId` 传 0 / 空 / 他人孩子 id / 超大 id | `canAccessChild` 拦截 → 403；`childId=0` 在埋点里被当 null（后端真值判断，需确认无副作用） |
| B-10 | `limit` 传 0 / 9999 / 负数 / 非数字 | 后端夹取到合法区间，不报错；前端不白屏 |

### 4.2 状态与并发边界

| # | 用例 | 预期 |
| --- | --- | --- |
| B-11 | 同一任务先存草稿再正式提交 | 草稿被更新为 submitted，不产生两条记录 |
| B-12 | 正式提交后再提交 | 409 `SUBMISSION_EXISTS`，提示「该任务已提交，请勿重复提交」 |
| B-13 | 家长提交后教师立即点评，家长端同时刷新 | 无脏数据，最终一致 |
| B-14 | 教师删除已发布班级任务后再发布 | 每周一条，覆盖逻辑正确 |
| B-15 | 管理员删除家长账号 | 该家长立即失效、会话清理、绑定解除；其孩子数据按设计保留/清理（需与产品确认） |
| B-16 | 管理员删除学生账号 | 档案、专属任务、提交记录一并删除（后端注释声明），验证无孤儿数据 |
| B-17 | 管理员删除教师账号 | 任务保留但解除发布者；班级保留但解除负责教师 → 该班级**无负责教师**时的展示与编辑 |
| B-18 | 教师对同一提交重复点评 | 允许，前端取最新；验证不产生重复通知 |
| B-19 | 家长提交关注后教师已审核，家长再编辑 | 已审核记录不可再改 |
| B-20 | 孩子被多个家长绑定 | 两端看到同一孩子数据一致；切换孩子不串号 |

### 4.3 空数据与首用边界

## 9. 维度九：错误提示与恢复机制

| # | 场景 | 预期表现 |
| --- | --- | --- |
| E-01 | 401 登录失效 | 清 session → toast「登录已失效，请重新登录」→ 800ms 后 redirect 登录页；**不能出现「点了没反应」** |
| E-02 | 403 无权限 | 直接展示后端 `message`（如「仅教师或管理员账号可访问」），duration 2500 |
| E-03 | 4xx 业务错误 | 展示后端 `message`（如「请填写提交内容」「该任务已提交，请勿重复提交」），**不展示技术性错误码** |
| E-04 | 5xx | 后端统一替换为「服务器暂时无法完成请求」；前端 GET 自动重试一次，重试仍失败给友好提示；**提供重试入口** |
| E-05 | 网络失败 | 区分：域名白名单 / 超时 / 证书 / 通用网络异常（api.js 已实现） |
| E-06 | AI 失败降级 | 每个 AI 功能点都有本地兜底：`aiStatus: fallback`、建议显示「本地规则兜底」、点评显示 warning、报告 `aiError` 提示；**不得白屏或空列表** |
| E-07 | 上传失败 | 区分 404（后端未部署上传接口 → 「线上后端尚未部署附件上传接口」）、413、503 |
| E-08 | 语音转写未配置 / 后端版本旧 | 两档降级弹窗文案不同（`unconfigured` / `outdated`），且引导直接输入文字 |
| E-09 | 表单校验失败 | 错误定位到字段、输入时实时清除错误、提交按钮恢复可用 |
| E-10 | 中断后可恢复 | 提交/发布/上传中途失败，用户数据（已填内容、已选附件）不丢失 |
| E-11 | 页面加载失败 | 提供「重试」按钮（timeline/feedback/submission-detail/admin 各页），不是空白页 |
| E-12 | 埋点失败 | 完全静默，不影响用户 |
| E-13 | 错误可追溯 | 4xx/5xx 响应带 `requestId` 与 `X-Request-Id`；确认前端在关键失败处可上报（建议：提 bug 时附 requestId） |
